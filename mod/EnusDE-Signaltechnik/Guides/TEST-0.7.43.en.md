# 0.7.43-P0 — Setup and game acceptance

Start with a save copy. Use matching 0.7.43 on host/clients. Existing route and
block checks remain enabled.

1. Open an auxiliary destination → Destination by clicking. Recognize its unique
   connected entry or pick it in the diagram/world. Verify the opposite approach
   and save the field. Rename/move its reference and verify the derived position.
   Active routes must block modification; deleted references must not reuse stale coordinates.
2. Open advanced settings and change track/metres/approach manually. This explicitly
   unlinks automatic following. Existing manually configured targets must still work.
3. Choose both neighbours in line setup. Complete unique signal duties or click
   each endpoint in its diagram. Add the read-only neighbour entry indication.
   Check path/GFM, then Apply. No local operation of the neighbour indication.
4. After full clear proving, exactly the granted permission arrow should be filled.
   Requests remain separate. Disabled/faulted lines must not display granted authority.
5. Sandbox: detect a point-free line with exact active detector endpoints. Preview
   three blocks: two inner boundaries. Edit distances and update preview. Changing
   the operating interlocking needs a new preview. Optional contacts include next-block
   targets; global automation stays unchanged. Confirm, inspect objects/sections/
   diagram and run both directions. Other-owned block signals are operated at their
   owning local interlocking or the master.
6. Economy: repeat with supplies required. New objects must stay planned until built.
   Stale proposals after construction/configuration changes must reject. A point
   area in the line must stop this plain-line construction assistant.
7. In Select mode drag one field and a group: translucent green/red destination,
   grab offset retained, Escape/outside drop cancels, collisions do not overwrite.
   Check Undo and original number identities/bindings. Separately verify drawing,
   placement, scrolling and panning over empty space.
8. Set two independent routes sharing a compatible protecting point. Both may
   clear only when their actual footprints do not violate protection. Opposite
   point demand or traversing a flank corridor must reject. Releasing one must
   retain the other's protective lock. Include a shunting-route counterpart.
9. Configure existing contact primary/alternate targets by diagram. Test contacts,
   save/reload, source IDs, new classifications, block displays and client indication.
   Old proceed authorities must still start at Stop after loading.

For failures record exact version, actions, message and diagnostic export. These
are pending game-acceptance steps, not claims of executed Unity/multiplayer tests.
Autonomous siding/crossing control and vehicle-specific bot order chains are not
part of this build.
