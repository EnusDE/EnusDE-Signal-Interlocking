# Module problems and next steps — 0.7.71

Host: open an interlocking in the editor, choose Menu → Set up and check → Module problems and next steps. The dispatcher's module-problem tool also opens this editor check. Existing Refresh and inspect installation opens the same overview.

Choose **Check modules again** for a new snapshot. Findings are grouped by interlocking and identify the functional module, affected item, problem, operating effect and next step. Diagram fields use one-based column / row. Open the affected interlocking's diagram directly; GFM inspection, world bindings, saved routes, line/GWB connections and retained locks have separate links. Long lists have pages of 25 findings. Technical details are optional and retain original IDs and game messages.

Checks cover saved detection paths and boundaries; missing signal/auxiliary references and competing train-number owners; missing points and incomplete enabled point detection; invalid saved route paths and flank calculation; active faulted routes; known line errors; failed game/waypoint integration; missing optional packs and the last provider rendering error. GFM diagnostics distinguish missing, unfinished, disabled and moved boundaries, point-arm links, missing/invalid track intervals, interrupted paths, branching, point crossings and skipped boundaries. These are causes found by the checks, not guesses from error strings.

Example: **Track detection (GFM) · Detection section → The section crosses a point instead of ending at its detection boundaries → Check the point's detection arms and detect/review adjoining sections again.** This identifies a detection problem, not automatically a missing shunting signal or a missing flank-protection element. Auxiliary destinations, detection boundaries and protective signals have separate purposes.

This is a host/editor read-only inspection, not an automatic repair or a continuous health monitor. Normal occupancy, waiting, intentionally disabled connections and paused automation are not faults by themselves. Unknown check failures remain explicitly unverified. Not every automatic request, unconfigured track gap or current occupancy is inspected. Existing GFM coverage tools and live locomotive/request views remain necessary. Line errors reflect the currently known runtime state; the provider error is its last reported error and may already have recovered. A clean report does not grant movement permission or prove complete detection coverage.

World/configuration changes mark the snapshot outdated; repeat the check. Live state can change immediately after inspection. Opening a stale affected-interlocking shortcut is refused. **Refresh all installation elements** remains a separately labelled maintenance action; the problem scan never changes route locks, track detection, signal commands, permissions or automation settings.

Before normal use, test visibility/navigation, malformed bindings, moved GFM, module exceptions, paused/occupied states, missing pack fallback, retained faults, save/reload and host/client behaviour in a disposable copy. Clients do not run the host/editor scan. Offline checks do not replace gameplay acceptance. No game launch, installation or public release was performed.
